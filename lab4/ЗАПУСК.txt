ЛР4. Приём вторсырья: аутентификация и авторизация

Открыть эту папку lab4 в IntelliJ IDEA как Maven-проект. Нужен JDK 21.
Главный класс: com.example.lab4.Lab4Application.

Первый запуск
1. В pgAdmin создать НОВУЮ базу recycling_lab4 с владельцем postgres.
   Базу recycling_db из ЛР3 оставляем как есть.
2. В Query Tool новой базы от postgres выполнить database.sql целиком один раз.
   Используется уже созданная в ЛР3 роль recycling_app.
   SQL создаёт таблицы, права и примеры данных; паролей учётных записей в нём нет.
3. В Run → Edit Configurations → Lab4Application → Environment variables указать:
   DB_PASSWORD — свой пароль роли recycling_app;
   ADMIN_EMAIL — email первого администратора, например admin@example.com;
   ADMIN_PASSWORD — свой пароль администратора.
   Пароль: не менее 12 символов; заглавная и строчная буквы, цифра и спецсимвол.
   Максимум 72 байта UTF-8. Пароли третьей лабы программа не читает.
   DB_URL по умолчанию jdbc:postgresql://127.0.0.1:5432/recycling_lab4,
   DB_USERNAME по умолчанию recycling_app. При необходимости задать их явно.
4. Запустить Lab4Application. Первый ADMIN создаётся один раз до открытия HTTP-порта.
   После создания можно убрать ОБЕ переменные ADMIN_EMAIL и ADMIN_PASSWORD.
   Повторный запуск не меняет пароль и роли уже существующих учётных записей.

Как проверить
1. Скопировать http-client.private.env.json.example в http-client.private.env.json.
2. В полученном файле указать те же ADMIN_EMAIL и ADMIN_PASSWORD.
   Этот приватный файл исключён из Git. Пример не содержит действующего пароля.
3. В requests.http выбрать environment local и Run All Requests in File.
   Это 64 проверки безопасности, прав, бизнес-операций и очистки своих данных.
4. acceptance.http — ещё 66 бизнес-проверок из ЛР3 с Basic Auth и CSRF.
   Запускается тем же способом. Отрицательные ответы 400/401/403/404/409 ожидаемы.
   Во время полного запуска не выполнять параллельно другие изменения данных.
   При прерывании могут остаться тестовые профили и записи с пометкой ЛР4.

Авторизация
USER: свои профиль, партии, бонусы и сводка; изменение своего имени/email;
      чтение справочников и поиск подходящих пунктов.
OPERATOR: чтение данных клиентов; приём, изменение и отмена партий;
          приём с бонусом и корректировка веса. Начисление бонусов запрещено.
ADMIN: CRUD, начисление бонусов, назначение ролей и блокировка входа.
       Свою роль/блокировку и удаление собственного профиля менять нельзя.
Ограничения лимитов, отмены и уже начисленных бонусов действуют для всех ролей.
POST /api/users создаёт профиль клиента без учётной записи.
Для создания учётной записи используется POST /api/auth/register; роль всегда USER.
Повышение роли и enabled доступны только ADMIN через PATCH /api/auth/accounts/{userId}.

HTTP Basic и CSRF
Логин — email. Каждый защищённый запрос требует Authorization: Basic.
GET /api/auth/me проверяет вход и возвращает профиль без пароля и хеша.
GET /api/auth/csrf возвращает token и headerName, а также cookie JSESSIONID.
POST/PATCH/DELETE, включая регистрацию, требуют ту же cookie и X-CSRF-TOKEN.
HTTP Client сохраняет cookie автоматически. После перезапуска нужен новый токен.
Роли и блокировка перечитываются из БД при каждом входе; cookie не заменяет пароль.
401 — нет действующих данных для входа; 403 — нет прав или неверный CSRF;
400 — неверные входные данные; 409 — конфликт с бизнес-правилами/данными.

Сборка
mvn package
55 автоматических тестов выполняются без подключения к PostgreSQL.
Готовый исполняемый файл: target/lab4-1.0.0.jar.
Приложение слушает 127.0.0.1:8080. Другой порт: переменная SERVER_PORT.
Папки .idea, target и приватные настройки в Git добавлять не нужно.
